# WebUI V2 草稿与升级兼容

草稿本身不是模块规则：保存、导入和导出都不会触发模块重载或应用。

要让逐应用设置真正生效，必须显式点击「应用到模块」并再次确认。该动作只把本次明确修改的应用合并到现有规则。旧配置不可读、同一应用有并发改动、预检查不通过或缺少内核回执时，不覆盖原文件。重开 WebUI 会重新读回保存的配置，且不会把磁盘配置等同于运行状态。它不会改写 `target_path.conf`、`scope_mode.conf` 或任何旧版规则文件。

## 升级和回退

| 场景 | 行为 |
| --- | --- |
| 旧版升级至新版 WebUI | 原有配置文件、默认值及读取规则不变。仍从「旧版规则」管理。不会自动将配置转换成逐应用规则。 |
| 检查黑名单旧配置 | 只统计上一次读取的配置中路径、包名与直接 UID 的条目，并提示需要核对的路径。不会生成或应用新规则。 |
| 检查白名单或全局模式 | 只读提示无法靠枚举当前安装应用等价转换，不改变模式。 |
| WebUI 更新、刷新、重开 | 未应用的草稿存于当前会话；已保存的模块配置会重新读取。更新前在「应用 → 草稿备份与升级兼容」生成备份，复制到用户控制的文件，之后粘贴恢复。 |
| 回退到不支持草稿的 WebUI | 旧配置仍可使用。保留独立的 V2 JSON 备份，恢复到支持此格式的 WebUI 后再导入。 |
| 草稿前端资源尚未加载 | 「应用」入口回退到旧规则编辑器，避免因可选资源丢失而无法管理旧配置。 |
| 不支持的备份版本或损坏输入 | 整份拒绝，保留输入和现有草稿。不降级解释、不部分导入。 |

## V2 草稿备份格式

- 根对象标识为 `format: "pathmask-profile-drafts"`，包含 `schemaVersion: 2` 和 `profiles` 数组。
- 每条记录以 `userId` 和 `packageName` 组成标识。未知 Android 用户为 `null`，不会自动映射为主用户。UID 不作为持久标识。
- 记录保留草稿中的开关和路径。导入不覆盖任何已保存草稿或未保存更改，即使备份中存在同一标识。
- 拒绝重复应用标识、重复路径、相对路径、根目录、控制字符、逗号、分号和超过 255 个 UTF-8 字节的路径。备份限制为 1,048,576 个字符、1024 个应用草稿；每个草稿最多 256 条路径。

直接输入的旧 UID、分组、模式路径和其他设备级行为都不被自动复制。兼容预览不接触正在运行的配置。
